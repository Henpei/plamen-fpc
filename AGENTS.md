# PLAMEN — AGENTS.md (project memory, maintained by the agent)

## What this is
PLAMEN — hardcore isometric action RPG. Side 2 build: **Free Pascal, FPC 3.2.2 x86_64 (`/usr/bin/fpc`), compiled from terminal, no IDE. Renderer: raylib 6.2 (`libraylib.so`, hand-written bindings in `src/raylib.pas`).**

## Build & run (always from repo root)
- `make` / `make all` — writes `src/version.inc` (git hash) and compiles `build/plamen` with fpc.
- `make run` — build + run the game (needs a display; without `DISPLAY` the binary exits loudly with RC=2, by design).
- `make selftest` — build + run `build/plamen selftest` headless; RC=0 = all pass (currently 82), log in `selftest.log`.
- `./build/plamen shot` — scripted graphical smoke run (title/chargen/hub/combat screenshots `shot_*.png`, then exits). Requires DISPLAY.
- `make clean`.
- Content bulk is generated: `python3 tools/gen_content.py` (deterministic; rewrites skills/builds/uniques/lore/quests_side/maps). Hand-edit story-critical files (quests.dat, dialog.dat, rules.dat, npcs.dat, monsters.dat, drops.dat...).

## Layout
- `src/plamen.dpr` — entry point, arg parsing (`selftest`), state machine.
- `src/raylib.pas` — raylib C bindings (subset we use). Extend here when needed.
- `src/core.pas` — logging, fatal/loud errors, CRC32, RNG, version stamp, text utils. **No raylib calls in core/data/sim/maps/selftest** so selftest runs headless.
- `src/data.pas` — generic data-file parser + typed registries. All game content lives in `data/*.dat`, never in code branches.
- `src/sim.pas` — pure game logic: stats, XP, combat math, loot, store, quest-state DB, save/load. No raylib.
- `src/maps.pas` — map loading (ASCII grids in `data/maps/`), collision, iso projection, spawn markers.
- `src/render.pas` — all raylib rendering, input, screens/UI, HUD. Only unit that talks to raylib besides the dpr.
- `src/selftest.pas` — headless test suite.
- `data/` — all content. `data/maps/` — ASCII maps. `tools/` — build scripts, map generator.
- `saves/` — runtime save slots (gitignored). `build/` — compiler output (gitignored).

## Conventions
- FPC `{$mode objfpc}{$H+}` everywhere. PAnsiChar for raylib strings.
- **NO SILENT FALLBACKS (law)**: missing file / bad data / corrupt save = loud fatal error via `Fatal()` (console + `error.log`), nonzero exit. Never substitute defaults silently.
- SGT loop: diagnose → small fix → `make selftest` → commit → (push if remote exists). One logical change per commit.
- Version stamp: `src/version.inc` is generated by `tools/build.sh` from `git rev-parse --short HEAD` at build time; HUD must show it every frame together with map name + act/region.
- Data files: INI-ish sections `[type:id]`, `key=value`, `#` comments, lists pipe-separated (`a|b|c`). Loader errors are fatal and name file+line.
- Maps: first lines `key=value` header (`name`, `region`, `act`, `kind=hub|area|dungeon`, `w`, `h`, `tileset`), then exactly `h` rows of `w` chars. Legend in `data/maps/LEGEND.txt`.
- Swedish UI text is fine (UTF-8); font is loaded with explicit codepoints incl. åäö ÅÄÖ.
- New content (monster/spell/item/quest/lore) = data file entry only; selftest `data_add_monster` proves it.

## Known platform pitfalls (learned the hard way, do not rediscover)
- fpc objfpc mode: **no inline `var` statements mid-block, no `for var` loops, no expression-position `if..then..else`, no multi-statement `case` branches without begin/end, and `and` binds TIGHTER than `=` (always parenthesize `(a = b) and c`)**. `tools/hoist_vars.py` hoists inline vars if needed. Reserved words bit us: `label` is reserved (use `caption`/`lab`).
- raylib needs a display + GL. Headless box: use `selftest` arg; graphical run without DISPLAY fails loudly (RC=2) — intended.
- raylib 6.x: `LoadFontEx` wants an explicit codepoint array; default font lacks åäö. We load DejaVu with codepoints 32..126 + åäöÅÄÖ + dashes (see `render.LoadGameFont`; none found = fatal). `IsFontReady` does not exist in 6.2 — it is `IsFontValid`.
- raylib `DrawTriangle` culls clockwise winding (y-down screen): tiles must be drawn CCW or they vanish (found via shot_*.png).
- fpc + raylib: `{$linklib raylib}` works because `libraylib.so` is in `/usr/lib`.
- Open-array (`array of T`) params cannot be SetLength'd — use named dynamic types (`TItemArr`, `TFlatArr` in sim).
- Save files: magic `PLAMSAVE` + version + CRC32 (case-insensitive hex compare!) of payload; tamper/corrupt = rejected loudly, never auto-repaired. Field separator inside save lines is `;` because item stats use `|`.
- raylib 6.2: `GetMouseRay` does NOT exist — the 6.x name is `GetScreenToWorldRay` (linking fails otherwise). Camera is `TCamera3D` with `projection = CAMERA_ORTHOGRAPHIC`; for ortho, `fovy` is the near-plane HEIGHT in world units.
- raylib 6.2 `GenMeshCube/GenMeshSphere/GenMeshCylinder/...` **SIGFPE sporadically when called from FPC** (integer div-by-zero inside the C lib; FPC unmasks FP exceptions, and the trap fires in raylib). Do NOT use GenMesh* — build meshes by hand and `UploadMesh` (see `render.BuildCubeMesh` / `AddFace`; CCW outward faces or the depth-cull eats them).
- Hand-written raylib bindings: large records (Mesh/Model/Material/Camera3D) passed BY VALUE with `cdecl` work on x86_64 SysV (sret/memory class) — declare them as plain by-value params, `PMaterial`/`PMesh` pointers for out-params like `SetMaterialTexture`/`UploadMesh`.
- 3D picking: `GetScreenToWorldRay(mouse, cam3)` then intersect the z=0 plane manually (`t = -pos.z/dir.z`) — do not rely on `GetRayCollisionQuad` winding.
- `DrawCircle3D` flat on the ground: use rotationAxis (1,0,0), angle **-90** (positive 90 faces away from an iso camera at +x+y and gets culled).
- git: remote `origin https://github.com/Henpei/plamen-fpc.git` is pre-authorized by the user — `git push origin main` after EVERY commit. Sandbox policy sometimes blocks chained `commit && push` or bulk file writes; when blocked, split the command or stage via the scratchpad and copy.
- When splicing files by line numbers, re-grep the markers in the SAME command right before splicing — parallel edits shift line numbers and a stale splice truncates procedures (bit us once; fixed by hand).

## Render rebuild 2 pitfalls (v3 low-poly renderer, added after 5d25dc1)
- **raylib TMatrix is ROW-major: `v * M`, and `MatrixMultiply(left, right)` applies LEFT first** (verified with a standalone fpc test: `MM(Translate(10,20,0), Scale(2,3,4))` yields translation (20,60,0)). Compose models as `Scale * Rotate * Translate` — i.e. `MatrixMultiply(MatrixScale(...), MatrixMultiply(MatrixRotate(...), MatrixTranslate(...)))`. Getting this backwards scales world positions into the map corner (rigs/props rendered at wrong spots while 2D labels stayed correct).
- **UInt64 underflow**: `NextRnd mod 100 - 50` on a UInt64 underflows to ~1.8e19 when the mod result < 50. Always `Integer(NextRnd mod 100) - 50`. This flew the camera to 1e17 on random frames during screen shake → entire 3D scene clipped to black while the 2D HUD stayed fine (misleading "zoom black" bug).
- Shadow map recipe that works: `LoadRenderTexture(1024)`, depth-encode FS (`gl_FragCoord.z` into RGB via fract), light camera `CAMERA_ORTHOGRAPHIC` with `fovy = 2*halfExtent`, in the lit shader compute `sc = (shadowVP * worldPos).xyz/.w * 0.5 + 0.5`, bind the RT on slot 1 (`rlActiveTextureSlot(1); rlEnableTexture(rt.texture.id); rlSetUniformSampler(loc, 1)`), slope-scaled bias `0.0028 + 0.008*(1-NdotL)`, shadow floor 0.34. `shadowVP := MatrixMultiply(MatrixLookAt(...), MatrixOrtho(...))` (raylib row-major order).
- Custom shaders via `LoadShaderFromMemory`: raylib auto-binds the default loc names `mvp`, `matModel`, `colDiffuse`, `texture0` for `DrawMesh`; custom uniforms need `GetShaderLocation` + `SetShaderValue`/`SetShaderValueMatrix` once per frame inside `BeginShaderMode`. `DrawMeshS` (render.pas) swaps `mat.shader` per draw so one mesh set can render in both the depth and lit passes.
- `TakeScreenshot` called after `EndDrawing` captures the last PRESENTED frame — scripted shots must require their condition to hold for several frames before capturing.
- Textures are 100% procedural (`GenImageColor` + pixel passes, 64x64, bilinear+repeat) — no asset downloads in this environment; credit-free by construction. If CC0 packs are ever bundled, credit them in README.
- `rlDisableBackfaceCulling()` once at init — hand-built meshes don't guarantee winding; culling then eats faces randomly.
